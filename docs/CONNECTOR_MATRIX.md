# Connector capability matrix

Status definitions:

- **Fully implemented and tested:** works end to end in automated tests with real files and SQLite, including the real Electron app.
- **Implemented, untested live:** a driver exists and passes mocked-protocol tests, but no live or staging system was available.
- **Requires configuration or vendor access:** no driver can work until the merchant obtains API access, a licence or a pinned official contract.
- **File-import-only:** supported through the vendor's own stock export saved as CSV/XML/JSON and an explicit CSV import profile. No native API.
- **Unsupported:** no implementation and no real integration path identified.

No vendor API, schema, COM interface, credential or export format was invented. Vendor names identify compatibility targets only.

## Generic sources

| Source                                                      | Status                            | Notes                                                                                           |
| ----------------------------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------- |
| CSV / XML / JSON handover file                              | Fully implemented and tested      | Standard schema or explicit CSV profile; 16 MiB / 100,000 rows; negative-stock rule.            |
| Local inventory (built-in, optional)                        | Fully implemented and tested      | Products, locations, adjustments, CSV import, barcode lookup; read-only source.                 |
| Local API / command-line / GUI automation / direct database | Unsupported (setup metadata only) | The wizard stores references, but never executes commands, automates clicks or opens databases. |
| XLSX / DBF parsing, folder watching                         | Unsupported                       | Save as CSV. Export scheduling reads the configured file on each interval instead of watching.  |

Each connection has its own permission (read-only by default), status, test, credentials and error isolation; a failing destination does not stop others. Two-way groups require CAS on every member, an agreed baseline, conflict holds and duplicate-free operation IDs. Last-writer-wins is never used. See [UNIVERSAL_SYNC_ARCHITECTURE.md](UNIVERSAL_SYNC_ARCHITECTURE.md).
